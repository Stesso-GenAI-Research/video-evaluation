\begin{abstract}
A person searching for instructions to remove a faucet needs to find the
removal step, even when an installation video uses many of the same words.
This study examines whether representing actions, objects, and tools explicitly
can help distinguish these instructions. I compare lexical TF--IDF matching,
structured matching, and an equal-weight combination using human-written
annotations from \VideoCount{} videos. After validation and deduplication,
the dataset contains \ClipCount{} clips. A development benchmark uses
\QueryCount{} clip names as queries and searches \CandidateCount{} clips
without using their names or parent-video text as candidate evidence.
Lexical matching achieves \LexicalHitOne\% Hit@1, compared with
\StructuredHitOne\% for structured matching and \HybridHitOne\% for the
combined method. Lexical matching also leads on two constructed pairwise
datasets. Cleaning inventory fields removes identified parsing defects, but
the tested synonym rules do not improve aggregate Hit@1. The results suggest
that the current action representation loses useful matching evidence.
Independent human judgments and evaluation on new videos are still needed
to determine how these findings extend to actual search preferences.
\end{abstract}

\section{Introduction}
Finding a useful instructional clip can depend on a small difference in
wording. Someone replacing a faucet may first need to loosen its fittings
and remove the old fixture. A search result showing how to install a new
faucet shares the object and much of the surrounding vocabulary, yet skips
the step that person needs. This problem led me to examine whether a search
system could use the action, its object, and the relevant tools to make a
more precise match.

I began with human-written annotations that describe individual steps in
instructional videos. These records provide a practical starting point
because they already identify short clips and describe the work taking place.
They also expose a difficulty that ordinary word matching does not fully
address. One annotation may describe ``plasterboard,'' while a person searching
for the same material writes ``drywall.'' At the same time, two tools listed
as possible substitutes should not automatically become synonyms. Treating
those relationships carefully is necessary if normalization is to preserve
what the annotation means.

Through this project, I compare ordinary word matching with an explicit
action representation and a combination of the two. I also test whether
cleaner inventory parsing and a small terminology lexicon change retrieval
performance. The experiments provide a working comparison on the available
data, but their targets come from the annotations themselves. Human authorship
of those annotations does not establish which of two clips a viewer would
prefer. That separate question remains part of the human evaluation.

\section{Related work}
Instructional videos have been used to study how language can identify
actions in visual content. Miech et al.\ developed HowTo100M using narrated
instructional videos and automatically transcribed speech to learn a shared
representation of text and video~\cite{miech2019howto100m}. Their work connects
a written request with visual evidence across a large collection. The present
study has a narrower scope: it searches human-written clip annotations and
does not learn from video frames or audio. Its results therefore describe
annotation retrieval, rather than a direct comparison with a learned
text--video model.

Zhukov et al.\ examined how instructional steps can share action and object
components across tasks~\cite{zhukov2019crosstask}. Their CrossTask work uses
narration and ordered step lists to learn visual models with weak supervision.
This supports the motivation for considering what an action operates on,
since an action or object alone may occur in many different steps. Here,
those components are extracted from text and compared using fixed rules.
Whether that simpler representation helps retrieval is an empirical question;
the results below show that it does not outperform the lexical baseline on
the current benchmark.

Terminology normalization also draws on established vocabulary practices.
The Simple Knowledge Organization System distinguishes a concept's preferred
label from alternative labels and provides separate relations for broader,
narrower, and related concepts~\cite{skos2009}. That distinction is useful for
this dataset: two names for drywall can map to one preferred term, whereas
a tool offered as a substitute may serve a related purpose without being the
same object. The current implementation uses a small local rewrite table,
not a full SKOS vocabulary. It preserves ambiguous names until their context
can be reviewed.

\section{Methods}
\subsection{Lexical baseline}
The lexical baseline gives more weight to words that help distinguish one
clip from the rest of the collection. It represents individual words and
adjacent word pairs using TF--IDF features. The vectors are normalized to unit length, so their
dot product gives cosine similarity~\cite{sklearn}. The retrieval benchmark
fits the vocabulary on candidate fields only and uses raw term frequency.
The existing search and pairwise-evaluation path uses sublinear term
frequency, $1+\log(\mathrm{tf})$, for positive counts. These configurations
are retained as implemented rather than changed after observing results.

The candidate fields also differ by evaluation. The field-held-out benchmark
excludes clip names and parent-video text. The frozen pairwise evaluator uses
the existing search representation, which includes those fields and weights
the clip title twice. Direct comparison of percentages across these two
experiments would therefore be inappropriate.

\subsection{Structured matching}
The parser uses spaCy tokenization, part-of-speech tagging, lemmatization, and
dependency relationships~\cite{spacy}. It extracts action records with an
action lemma, object terms, directly attached tool terms, and negation.
Tool and supply inventories provide separate record-level context. An
inventory item is not assumed to be grammatically attached to every action.

An exact action-lemma match receives a score of one. Otherwise, shared
VerbNet classes and FrameNet frames provide weaker matching evidence.
VerbNet groups verbs using syntactic and semantic patterns~\cite{verbnet};
FrameNet supplies frame-semantic descriptions~\cite{baker1998framenet}.
For sets of labels $X$ and $Y$, let
\begin{equation}
 J(X,Y)=\frac{|X\cap Y|}{|X\cup Y|},
\end{equation}
with zero assigned when there is no shared evidence. If $V$ denotes VerbNet
classes and $F$ denotes FrameNet frames, action similarity is
\begin{equation}
 A(q,c)=
 \begin{cases}
  1, & \text{if the action lemmas match},\\
  \max\{0.80J(V_q,V_c),\;0.70J(F_q,F_c)\}, & \text{otherwise}.
 \end{cases}
\end{equation}
Object matching measures the fraction of query object terms found in the
candidate. Tool and supply comparisons use the same directional coverage
principle. Their strongest applicable match supplies a context score $C$.

For one query action and one candidate action, the score has the form
\begin{equation}\label{eq:structured}
 S(q,c)=\gamma A(q,c)
       \bigl(w_A A(q,c)+w_O O(q,c)+w_C C(q,c)\bigr),
\end{equation}
where the base weights are $(0.55,0.35,0.10)$. Weights for absent query object
or context evidence are removed, and the remaining weights are renormalized.
The confidence multiplier is $\gamma=0.90+0.10\min(p_q,p_c)$, where the $p$
values are extraction confidences. A negation mismatch forces the score to
zero. The strongest candidate action is selected for each query action, and
the resulting scores are averaged. A learned exploratory action taxonomy is
recorded for diagnostics but does not affect ranking.

I also combine the two scores to test whether explicit action information
can improve the lexical ranking. This fixed hybrid uses
\begin{equation}
 H(q,c)=0.5L(q,c)+0.5S(q,c),
\end{equation}
where $L$ is the lexical score. The search and pairwise paths fall back to the
lexical score if no query action can be parsed. The retrieval benchmark instead
excludes such queries while retaining their clips as possible distractors.
No hybrid-weight sweep is used to select the reported result.

\subsection{Inventory cleanup and terminology normalization}
While examining the inventory fields, I found that splitting every comma
could break a valid list inside parentheses. The parsed names also retained
placeholders such as ``Unknown'' and ``Unspecified,'' which supplied no useful
tool information. I revised the parser to keep grouped lists together,
preserve usage notes, and remove these placeholders from the parsed names.
The original annotations remain available for inspection. Across the complete
index, mismatched-parenthesis flags fell from 111 to zero, and placeholder-name
flags fell from 91 to zero. These counts measure the formatting problems
identified by the audit; they do not establish that every inventory is correct.

The active lexicon contains nine directional rewrites covering six preferred
terms. Examples include ``gypsum board'' and ``plasterboard'' to ``drywall,''
``measuring tape'' to ``tape measure,'' and ``mitre saw'' to ``miter saw.''
The same normalization is applied to queries and candidate representations.
Attributes and original text are retained. Ambiguous terms such as ``tap,''
``mud,'' and ``Sheetrock'' have no global rewrite rule. The local annotations,
for example, use Sheetrock in the name of a joint-compound product.

A second, independent option excludes explicitly listed substitutes from
inventory evidence. It does not remove the original alternatives from the
metadata. This distinction is needed because a circular saw may be offered as
an alternative to a miter saw without being the same tool.

\section{Experimental design}
\subsection{Field-held-out retrieval}
The query is a clip name, and the known target is the same canonical clip.
Candidates are represented by descriptions, goals, tools, and supplies.
Candidates require a description or goal. Queries are excluded when their
normalized names are ambiguous, when their exact normalized phrase appears
in the target fields, or when an action cannot be parsed. Excluded queries
remain candidate distractors. The resulting experiment contains
\QueryCount{} queries and \CandidateCount{} candidates.

The benchmark reports Hit@$k$ for $k\in\{1,3,10\}$ and mean reciprocal rank
(MRR). Targets with non-positive scores receive zero credit. For a positive
score tied across ranks $a$ through $b$, Hit@$k$ receives the fraction of those
positions at or above the cutoff. Reciprocal-rank credit is
\begin{equation}
 \frac{1}{b-a+1}\sum_{r=a}^{b}\frac{1}{r}.
\end{equation}
Retrieval ties use a numerical tolerance of $10^{-12}$. Confidence intervals
resample whole source-video clusters, with 2,000 draws and seed 1729. The
within-video analysis restricts candidates to the query's source video.

All four terminology configurations use the same ordered query cohort and
index artifacts. New exact normalized query--target phrase matches are
recorded separately; none occurred in these runs. This check does not remove
all semantic dependence between a clip's annotation fields.

\subsection{Constructed pairwise development experiments}
The metadata-contrast dataset contains 800 steps and 2,395 comparisons selected
using parsed metadata rather than retrieval scores. The hard-negative dataset
contains 350 steps and 1,309 comparisons. It uses paraphrased requests and
alternatives selected using frozen scorer outputs. Both datasets designate
the clip supplying the request information as the winner. The hard-negative
selection is deliberately challenging and is not a random sample of user
requests.

The evaluator scores the supplied A/B clips directly. Agreement credit is one
when the designated winner receives a higher score, one-half for an exact
score tie, and zero otherwise. Intervals resample complete step clusters,
using 5,000 draws and seed 42. The October 6 run copied the earlier comparison
inputs unchanged, rather than regenerating winners after the code changes.
The two datasets are reported separately because their selection procedures
differ.

The planned human evaluation asks reviewers to inspect both clips for a
given request and record a preference, a tie, or an inability to judge.
A diagnostic packet samples 44 development comparisons and 60 extraction
examples. Its scores were recorded before review, and the analysis retains
abstentions and missing responses. Because the cases were selected to examine
specific weaknesses, their results will describe those cases rather than
estimate performance on a new population. A separate test requires new videos
and independently supplied requests or preferences; all 250 current videos
have already informed development.

\subsection{Diagnostic findings}
Table~\ref{tab:diagnostics} records overlapping diagnostic flags. Structured
ties and zero evidence are frequent, especially in the hard-negative corpus.
These counts identify cases for inspection; they do not, by themselves,
establish whether a failure was caused by missing source information, an
incorrect parse, an inadequate lexicon, or the scoring rule.

A further audit partitions the 415 comparisons in which both structured
scores are zero. In 21 comparisons, the query has no parsed action. In 58,
one candidate has no parsed actions. In the remaining 336, the query and both
candidates have parsed actions, but both selected alignments have zero action
match. Thus about 81\% of these zero-score comparisons still contain parsed
actions on both sides. This narrows the next review to the extracted actions
and their compatibility, rather than treating every zero as an absent parse.
It does not establish a synonym error: negation mismatches or
different actions can also produce zero action match.

\section{Discussion and limitations}
I expected the action representation to help distinguish instructions that
share an object but ask the viewer to do different things. The results instead
show how much useful information can be lost when a match depends on a parsed
action. Equation~\ref{eq:structured} gives zero credit when action similarity
is zero, even if the object or surrounding text is relevant. The 336 comparisons
with parsed actions but zero action match make that behavior a useful starting
point for review. Inspecting those actions can help determine whether the
problem comes from extraction, semantic coverage, or a real difference between
the instructions.

The terminology experiment also changed how I interpret the data-cleaning
problem. Fixing broken lists makes the records easier to use and inspect,
but it does not necessarily improve the ranking. Likewise, the nine tested
rewrites resolve specific naming differences without improving aggregate
Hit@1. The lexicon is small, some alternatives already appear in the metadata,
and the benchmark does not deliberately sample regional expressions. Requests
written independently using those expressions would provide a more direct
test of the value of normalization.

The evaluation remains limited by how its requests and targets were formed.
A clip name and its description come from the same record, so they can share
meaning and wording even after exact phrase matches are excluded. Requiring
a description or goal also selects a smaller, more complete portion of the
dataset. The constructed pairwise winners add another dependency: they identify
the clip used to form a request, rather than a preference observed from a viewer.
Human review can assess the selected cases, but a broader performance claim
requires independently collected evidence. Dividing the existing videos into
new partitions would not undo their use during development.

End-state matching remains a separate, unfinished task. An intended result
such as a watertight seal is different from evidence that the seal was achieved.
Likewise, ``smooth,'' ``level,'' ``dry,'' and ``cured'' describe different
conditions. No validated end-state representation or evaluation is reported.

\section{Conclusion}
Through this study, I developed and evaluated three ways to match project
steps with annotated instructional clips. Lexical matching performs best on
the current development data. Cleaning the inventory fields removes specific
parsing defects, while the tested terminology rules leave aggregate Hit@1
unchanged. These findings direct the next stage toward examining which actions
the parser extracts and why apparently relevant instructions fail to match.
The prepared human review and a subsequent test on new data will help determine
whether revising that representation can improve the clips a viewer receives.

\section{Human review procedure}
A review packet has been prepared with the existing 60 extraction examples
and 44 diagnostic preference comparisons. The latter sample contains one
comparison per selected source step, with randomized A/B order and no model
scores or constructed winners shown in the worksheet. It includes eight
query-parse cases and twelve cases from each of three further diagnostic
groups. These groups guide case selection; they do not define the true cause
of an error. Reviewers receive blank response fields and no model scores.

Preference responses allow A, B, tie, and unjudgeable, with a blank response
treated as pending. The export tool preserves tie, unjudgeable, and pending
counts while exporting only observed A/B choices to the binary evaluator.
The sample is intended for diagnosis, so agreement on these cases must not
be presented as the final independent preference result.

The analysis compares each A/B decision with the corresponding scores saved
before review. It reports method agreement and paired differences from the
lexical baseline using 5,000 bootstrap draws over source-step clusters, with
seed 42. Extraction correctness is reported within the four sampling groups,
including the number of judged and unjudgeable entries. Blank fields remain
pending. If two reviewers participate, their A/B/tie responses can be compared
using raw agreement and Cohen's kappa; disagreements are retained for human
adjudication. No majority or preferred label is assigned automatically.

A prospective source-overlap check compares database identifiers, YouTube
identifiers, and normalized URLs with the development export. The current
250-video export fails this check against itself, as expected. Passing this
check would establish only that these identifiers are disjoint; it would not
detect every reupload or prove that queries and judgments were unseen.
